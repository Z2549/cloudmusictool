# 1.2.0 ABTest 实现契约（A/B 共用）

## 目标
只读展示实际命中的实验 + 按精确白名单强开分组。默认关，单 key 生效，手动恢复。

## 共享规则
- 白名单/黑名单唯一来源：`com.cloudmusictool.app.AbTestPolicy`（已由主代理创建）。
  - `CURATED_KEYS`：22 个安全 key。
  - `isBlocked(key)`：正则 + `boot-` 前缀。
  - `isAllowed(key, promoted)`：curated 或已提升，且不在黑名单。
  - `GROUPS`：`c/t/t1/t2/t3/t4`；`isValidGroup`。
- 禁止：全局默认 `t`、前缀放行、改 `status`/`clientConfig`、启动 AB 强开。

## 配置键（remote prefs，group=`config`）
- `abtest_force_map`：String，JSON 对象 `{"<key>":"<group>"}`。只存已开启的 key。
- 已提升 key = `abtest_force_map` 中不属于 `CURATED_KEYS` 的 key（不另存 promoted 集合）。

## 观测数据（目标进程 -> StatusProvider -> 模块 App）
`StatusProvider` 新增：
- `extras.putString("type", "experiments")` 与 `extras.putString("json", ...)`；
- 模块 App 侧 `StatusProvider.readExperiments(Context)` 返回 JSON String。

JSON 结构：
```json
{
  "updatedAt": 1730000000000,
  "items": [
    {"key":"tabMerge","group":"t1","source":"libra|old|startup","count":12,"lastAt":1730000000000}
  ]
}
```
上限：200 个 key、64KB；超限按 count 截断。

## 目标进程（实现 A）
- 新建 `hooks/AbTestHooks.java`：
  - `ABTestManagerImpl#checkExperiment(String,boolean)`：after hook 记录 key/group/source；若 key 在 forceMap 且原返回 null，返回合成的 `LibraABTestConfig`（失败则 `ABTestConfig`），字段 `abtestname=key`、`abtestgroup=group`、`status=1`、`clientConfig=new HashMap<>()`。
  - `ABTestConfig#getGroupKeys()` 与 `LibraABTestConfig#getGroupKeys()`：若 `this.abtestname` 在 forceMap，返回强制 group；否则 `chain.proceed()`。
  - `com.netease.cloudmusic.abtest2.b#x(String,boolean)`：after hook 记录；原返回 null 且 key 在 forceMap 时返回合成 config（兜底）。
  - `StartupABManager#getGroup(String)`：**只记录，不改值**。
  - `genericCheckExperimentWithParam`：本期不 hook（不改参数）。
  - 所有强开前用 `AbTestPolicy.isAllowed(key, promoted)` + `isValidGroup` 二次校验；日志 `ABTEST force key=... group=...`。
- 新建 `hooks/ExperimentState.java`：并发 map、count/lastAt、2 秒节流、flush 到 StatusProvider（type=experiments）、64KB 上限。
- `Config.java`：新增 `KEY_ABTEST_FORCE_MAP` 读取（String JSON）。
- `StatusProvider.java`：支持 `type` 分流，新增 `readExperiments`。
- `Hooks.java`：新增 `ABTEST` 的安装入口（不是 Feature 开关，固定随模块安装；或由 `Config` 的 `abtest_enabled` 控制，默认 true 只读、forceMap 为空时不强开）。建议：始终安装只读观测；forceMap 为空时不做任何修改。

## 模块 App（实现 B）
- 新建 `ExperimentFragment`（PreferenceFragmentCompat，程序化构建）：
  1. 顶部警告：“强开实验可能导致界面异常；每次只开一个；重启网易云生效；默认关闭”。
  2. “可强开实验”：22 个 curated key，每行显示当前观测 group + 强制 group（或“不强制”）；点击弹单选 `不强制/c/t/t1/t2/t3/t4`，写 `abtest_force_map`。
  3. “已探测实验”：读 `StatusProvider.readExperiments`，列出未收录 key；点击“提升为强开”（同样的分组单选），提升前用 `AbTestPolicy.isAllowed(key, promoted)` 校验；黑名单 key 显示为“禁止强开”且不可点。
  4. “已强开”：列出 forceMap 条目，可单独取消；“一键恢复默认”清空。
  5. “刷新”重新读观测数据。
- `ConfigStore`：新增 `getString(key,def)` / `putString(key,value)`。
- `MainActivity` + `nav_main.xml`：新增第 4 个 Tab「实验」；`ExperimentFragment` 分支。
- 新增 `ic_experiment.xml`、strings、必要的 layout。
- 所有写操作提示“重启网易云生效”；不提供自动回滚。

## 验收
- 冷启动后实验页能看到实际命中的 key。
- 强开 1 个安全 key（建议 `tabMerge`）→ 重启 → 日志 `ABTEST force` + 业务分组变化；取消后恢复。
- 尝试提升 `VIP_accountcard_01` → 被拒绝。
- 全程无崩溃/登录异常；`assembleDebug`/`assembleRelease`/单测/lint 通过。
