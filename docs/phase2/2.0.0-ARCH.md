# 2.0.0 架构说明：Profile / MountSpec / MountResolver

- 目标宿主：网易云音乐 **9.6.08**（versionCode 9006008）
- 代码基线：1.2.0（行为不变，仅重构挂载点定位）
- 文档日期：2026-10-20
- 适用范围：`com.cloudmusictool.app.profile`、`tools/check-mounts.sh`、`ProfileExportTest`

---

## 1. 目标与边界

2.0.0 不新增功能，也不改变任何 hook 的返回值或拦截逻辑。它解决的是**坐标散落**问题：

- 类名、方法名、参数/返回类型、DexKit 锚点从各 `*Hooks.java` 收口到 Profile；
- 代码与体检脚本共用同一份清单，避免“脚本写一套、代码写另一套”；
- 新增宿主版本时只新增一个 Profile 文件，不改 hook 体；
- 每个 Feature 标记 critical 挂载点，缺失时由 `MountResolver` / `HookState` 报告降级或不可用。

明确不做：

- 不承诺“任意新版本自动兼容”；只承诺白名单版本。
- 不改变 hook 行为；9.6.08 上与 1.2.0 等价。
- 不修改 `D:\quietbox`、`E:\download\base(2).apk` 等外部工程/样本。

## 2. 组件结构

| 组件 | 位置 | 职责 |
|---|---|---|
| `MountSpec` | `profile/MountSpec.java` | 一个挂载点的不可变描述：`id`、`featureId`、`logicalName`、`classCandidates`、`methodName`、`returnType`、`paramTypes`、`anchors`、`critical` |
| `TargetProfile` | `profile/TargetProfile.java` | 一个宿主版本的挂载点集合，提供 `forFeature` / `criticalCount` / `findClassSpec` / `findMethodSpec` |
| `Profile9608` | `profile/Profile9608.java` | 9.6.08 总表，拼装 `ProfileAdPv` 与 `ProfileUi` |
| `ProfileAdPv` | `profile/ProfileAdPv.java` | AD-01~AD-10、PV-01~PV-07、ABTEST 观测点 |
| `ProfileUi` | `profile/ProfileUi.java` | UI-01~UI-15（UI-04 无挂载点，按计划跳过） |
| `ProfileRegistry` | `profile/ProfileRegistry.java` | `versionCode` / `versionName` -> Profile；未适配版本返回 `null` |
| `MountResolver` | `profile/MountResolver.java` | `MountSpec` -> `Class` / `Method`；精确类名优先，失败后走 DexKit 锚点兜底 |
| `TypeResolver` | `profile/TypeResolver.java` | JVM 描述符（`Z`、`V`、`Ljava/lang/String;`、`[I`）-> `Class` |
| `ProfileExportTest` | `app/src/test/java/com/cloudmusictool/app/ProfileExportTest.java` | 导出 JSON 并校验清单一致性 |
| `check-mounts.sh` | `tools/check-mounts.sh` | 读取导出 JSON，对 APK 的 `classes` / `methods` 表逐项体检 |

### 2.1 解析顺序

`MountResolver.resolveClass`：

1. 按 `classCandidates` 顺序 `Class.forName`；
2. 校验类归属：`com.netease.*`，或由宿主 ClassLoader 加载且非 `com.cloudmusictool.*`
   （覆盖 `q60.w0` / `fw0.e` / `dr.h` 等顶层混淆类；DexKitLocator 使用同一规则）；
3. 若 `methodName` 非空，校验类中确实存在同名方法；
4. 精确匹配失败且 `anchors` 非空时，调用 `DexKitLocator.findClass` 做结构/字符串锚点兜底；
5. 结果按 `spec.id` 缓存；无法消歧时返回 `null`，不猜。

`MountResolver.resolveMethod`：

1. `paramTypes` 非空时，按精确参数类型在类及其父类中查找；
2. `paramTypes` 为空时，按方法名 + `returnType` 消歧，只有唯一候选才接受；
3. 最后再次校验返回类型；不匹配则拒绝。

### 2.2 critical 语义

- `critical=true`：该挂载点缺失时（类/方法找不到、hook 安装抛异常、返回类型校验不匹配），
  对应 Feature 标记 `degraded`（其余挂载点仍生效）。
- `critical=false`：可选增强；缺失只计入 `failed`，不单独触发降级。
- 每个有挂载点的 Feature 至少有一个 critical。UI-04 是 blocked Feature，没有挂载点。
- `expected` 保持 attempted 语义：`expected = installed + failed`，诊断卡显示真实的
  `installed/expected`（例如 AD-01 为 7/7），不再用 critical 数当分母。
- 安装结束调用 `finish(feature)`：`installed == 0` -> `unavailable`；
  `criticalFailed > 0` -> `degraded`。critical 判定由 `HookKit` 通过活动 Profile 的
  `findClassSpec` / `findMethodSpec` 得出，失败 label 去重后累加。
- ABTEST 不是 Feature，不参与 HookState 统计；其 5 条坐标只用于 Profile 定位。
  这两个字段由目标进程回写到模块 App，状态卡/诊断卡显示「降级」「不可用」。

## 4. 新增宿主版本

以 9.6.09 为例：

1. 复制 `Profile9608.java` 为 `Profile9609.java`，修改 `VERSION_CODE` / `VERSION_NAME`；
2. 复制 `ProfileUi` / `ProfileAdPv` 中需要调整的条目到新分片（或先复用 9.6.08 分片）；
3. 在 `ProfileRegistry.forVersionCode` / `forVersionName` 注册新版本；
4. 用 dexsql 对新 APK 逐条核对 class descriptor、参数/返回类型；
5. 把 `ProfileExportTest` 的导出对象改为新 Profile（或参数化导出多个版本）；
6. 运行 `bash tools/check-mounts.sh --apk <新APK> --profile <新JSON>`；
7. 全 OK 后再在真机上做冒烟；未适配版本仍由 `VersionGate` 拦截。

**不要**直接把 9.6.08 的 Profile 套到未知版本上并宣称兼容。

## 5. 导出 JSON 与 check-mounts

### 5.1 导出

```bash
cmd //c "gradlew.bat :app:testDebugUnitTest --tests com.cloudmusictool.app.ProfileExportTest"
```

输出：`app/build/profile9608.json`（从仓库根目录运行时同样落到 `app/build/`）。

字段：

```json
{
  "versionCode": 9006008,
  "versionName": "9.6.08",
  "mounts": [
    {
      "id": "UI-02/dr.h#T0",
      "featureId": "UI-02",
      "logicalName": "dr.h#T0",
      "classCandidates": ["dr.h"],
      "methodName": "T0",
      "returnType": "V",
      "paramTypes": ["Ljava/util/List;"],
      "anchors": ["RecommendTwoFlowAdapter"],
      "critical": true
    }
  ]
}
```

`ProfileExportTest` 同时断言：

- `id` 唯一；
- `classCandidates` 非空；
- 每个有挂载点的 Feature 至少一个 `critical`；
- 所有未 blocked 的 UI Feature 都有挂载点与 critical；
- 导出文件可回读，条目数与 Profile 一致。

### 5.2 体检

```bash
# 默认：E:/download/base(2).apk + E:/tools/dexsql/dexsql.exe + app/build/profile9608.json
bash tools/check-mounts.sh

# 显式参数
bash tools/check-mounts.sh --apk "E:/download/base(2).apk" \
    --dexsql "E:/tools/dexsql/dexsql.exe" \
    --profile app/build/profile9608.json

# 允许非 9.6.08 版本（只跳过版本断言，不改变检查项）
bash tools/check-mounts.sh --allow-version
```

环境变量：`APK`、`DEXSQL`、`PROFILE_JSON`、`AAPT2`、`ALLOW_VERSION=1`。

行为：

1. `aapt2 dump badging` 读取 `versionCode`，必须是 `9006008`（`--allow-version` 可跳过）；
2. 对每个 mount 的每个 `classCandidates` 查 `classes.descriptor`；
3. 有 `methodName` 时查 `methods` 表：
   - 优先使用 `param_descriptors` + `return_descriptor` 精确比对；
   - 旧版 dexsql 没有这两列时，退化为 `descriptor = "(<params>)<return>"` 匹配；
   - 要求 `method_kind IS NOT NULL`（排除纯接口/抽象声明）。
4. 输出 `OK` / `GONE`；工具或 SQL 失败输出 `ERROR`。`GONE` / `ERROR` 退出码非 0。

9.6.08 基线：`OK=133 GONE=0 ERROR=0`。

## 6. 行为等价与验证

- hook 文件仍保留原拦截体；Profile 只提供坐标，不改变返回值、日志与开关语义。
- 9.6.08 上 `ProfileUi` 的 63 个挂载点与 1.2.0 的 UI hook 一一对应；
  `ProfileAdPv` 的 70 个 AD/PV/ABTEST 挂载点由另一分片维护。
- 验证命令：

```bash
cmd //c "gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug"
bash tools/check-mounts.sh
```

- 真机只做模块 App 状态卡冒烟；不 reboot、不强制启动目标进程、不修改版本号。

## 7. 已知限制

- 只适配 9.6.08；其他版本默认跳过。
- UI-04 仍无可靠挂载点，保持 blocked。
- 部分 UI 挂载点没有 DexKit 锚点，只能精确类名匹配；类被重命名时该子项会报告缺失。
- `maybeDisplayHint` 等混淆方法依赖 9.6.08 的固定三参数签名；宿主改签名时 check-mounts 会报 `GONE`。
- `check-mounts.sh` 需要 `aapt2`、`dexsql` 以及 `python3/python` 或 `jq` 之一；缺失时明确报错。
