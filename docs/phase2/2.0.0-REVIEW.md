## 3. P1（发布前应处理）

### P1-1 Profile 只覆盖了“类名”，方法定位仍大量硬编码

`PHASE2_PLAN.md:216` 要求“hook 文件只保留取 MountSpec + hook 体”，但当前大量 hook 直接调用 `findMethodQuiet/findByNameQuiet/findByShape/findByNameAndArity`，完全绕过 `HookKit.resolveProfileMethod`：

- `app/src/main/java/com/cloudmusictool/app/hooks/HomeBlockHooks.java:54,69`
- `app/src/main/java/com/cloudmusictool/app/hooks/HintHooks.java:36,62`
- `app/src/main/java/com/cloudmusictool/app/hooks/AutoPlayHooks.java:26,42,56,61,75,89`
- `app/src/main/java/com/cloudmusictool/app/hooks/TopTabHooks.java:59,64,96,124,155,188`
- `app/src/main/java/com/cloudmusictool/app/hooks/BottomTabHooks.java:30,35,49,70`
- `app/src/main/java/com/cloudmusictool/app/hooks/UpdateHooks.java:52,63,67,77,81,93`
- `app/src/main/java/com/cloudmusictool/app/hooks/StatisticHooks.java:36,59,93`
- `app/src/main/java/com/cloudmusictool/app/hooks/AbTestHooks.java:91-92,123-124,146-147,177-178`（直接 `Class.forName`，5 个 ABTEST Profile 坐标完全未使用）

后果：新版本若只改方法名/字母名，Profile 无法接管；必须改 hook 文件。这与“新增版本 = 新增一个 Profile 文件”的 2.0.0 目标不符。9.6.08 上行为不变（已实测），但多版本价值被大幅削弱。

### P1-2 混淆类的 DexKit 锚点兜底实际不可用

`DexKitLocator.findClass` 在候选过滤时只允许 `com.netease.cloudmusic.*`：

- `app/src/main/java/com/cloudmusictool/app/dexkit/DexKitLocator.java:285`（`isTargetClass(c.getName())`）
- `app/src/main/java/com/cloudmusictool/app/dexkit/DexKitLocator.java:329-332`（只接受 `com.netease.cloudmusic` 前缀）

因此 `q60.w0`、`dr.h`、`th0.h`、`rh0.c`、`tt0.d`、`vt0.r`、`lv0.j`、`fw0.e` 这些混淆类的 anchor 即使命中也会被丢弃，`MountResolver.resolveClass` 的 DexKit 兜底（`app/src/main/java/com/cloudmusictool/app/profile/MountResolver.java:56-68`）永远返回 null。`2.0.0-ARCH.md:37/49` 的“精确类名失败后走 DexKit 锚点兜底”对这些类不成立。

注：这是 `DexKitLocator` 的既有问题，不是 2.0.0 引入；但 2.0.0 把它写进了多版本承诺，且 `2.0.0-ARCH.md:209` 只轻描淡写为“部分 UI 挂载点没有锚点”。建议把 `DexKitLocator.isTargetClass` 改成与 `MountResolver.isTargetClass` 一致的“宿主 ClassLoader 归属”判断。

### P1-3 HookState 的 critical 失败标记不完整，degraded 会漏报

`HookKit` 只在“类未找到/方法未找到”时传 `critical`：

- `app/src/main/java/com/cloudmusictool/app/hooks/HookKit.java:97,240-241,260-261,288-289`

但 hook 安装抛异常、返回类型不匹配时没有传 critical：

- `app/src/main/java/com/cloudmusictool/app/hooks/HookKit.java:410`（`hook:` 失败）
- `app/src/main/java/com/cloudmusictool/app/hooks/HookKit.java:430,438`（`rettype:` 失败）

`HookState.finish` 的 `degraded` 只由 `criticalFailed > 0` 驱动（`app/src/main/java/com/cloudmusictool/app/HookState.java:123-131`），所以 critical 挂载点“找到了但 hook 失败/返回类型不符”时不会置 degraded，只增加 failed。建议在 `install`/`validateReturnType` 失败路径也按 `isCriticalMount` 标记。

### P1-4 AD-02 漏一个真实挂载点：`LaunchDialog#showDialog(LaunchDialog,Context,int)`

`LaunchDialogHooks` 按方法名安装了 6 个方法：

- `app/src/main/java/com/cloudmusictool/app/hooks/LaunchDialogHooks.java:33-39`

Profile 只列了 5 个（2 参 `showDialog` 等）：

- `app/src/main/java/com/cloudmusictool/app/profile/ProfileAdPv.java:133-149`

APK 中 `showDialog` 有 2 参和 3 参两个定义，真机日志也确实出现 `LaunchDialog#showDialog(3)`。`docs/phase2/2.0.0-VERIFY.md` 写“AD-02 6/6”，正好说明运行时装的是 6 个，而 Profile 只有 5 个。因此 Profile 的“覆盖现有全部 hook”不成立，且 `check-mounts` 只做 Profile→APK 校验，无法发现 hook→Profile 的漏项。建议补 3 参坐标，或在 hook 中明确跳过。

### P1-5 架构文档与实现不一致（HookState 语义）

`2.0.0-ARCH.md:63-64` 仍写：

> `HookState` 在 Profile 模式下用 `expect(feature, criticalCount)` 设置期望值……`0<installed<expected -> degraded`

当前实现已没有 `expect`，`expected` 由 `attempted()`（installed+failed）维护，`degraded` 由 `criticalFailed` 驱动：

- `app/src/main/java/com/cloudmusictool/app/HookState.java:73-78`
- `app/src/main/java/com/cloudmusictool/app/HookState.java:123-131`

这会误导后续维护者和审查者。另外 `2.0.0-ARCH.md:194` 的“63 个挂载点与 1.2.0 UI hook 一一对应”也与 P1-4/方法硬编码现状不完全一致。

### P1-6 release 元数据仍是 1.2.0 / versionCode 4

- `app/build.gradle:19-20`：`versionCode 4`、`versionName "1.2.0"`
- 产物文件名 `cloudmusictool-1.2.0.apk`
- 但 `dist/release-notes-2.0.0.md` 已写“2.0.0（versionCode 5）”，`docs/phase2/2.0.0-VERIFY.md` 也写“版本号发布前 bump 到 5”

`CHANGELOG.md` 已注明“由发布分支统一调整”，所以若本工作区只做架构验证可不阻断；但发布说明与实际构建配置已经不一致，若这就是 2.0.0 交付物，必须在发布前改版本号，否则无法与 1.2.0 区分，且升级语义不明确。

## 4. P2（建议改进）

1. **UI-07 critical 标错重点**：`SettingActivity#V8` 是 critical，真正的自动播放门 `jn#m0`、`tt0.d#a/d`、`vt0.r#j`、`lv0.j#e` 全是非 critical（`ProfileUi.java:169-184`）。四个门全丢时仍可能显示健康。
2. **UI-06 critical 选择偏窄**：5 个 `maybeDisplayHint` 只有 `PushGuideHintView` 是 critical（`ProfileUi.java:146-164`），其余 4 个全丢不会降级。
3. **多候选类无消歧/拒绝**：`MountResolver.resolveClass` 按 `classCandidates` 顺序返回第一个存在的类（`MountResolver.java:37-55`），与 `2.0.0-ARCH.md:2.1` 的“无法消歧返回 null”不符。当前所有 spec 都是单候选，属于潜在问题；若将来启用多候选，可能返回与 hook 请求不同的类。
4. **同 class+method 多 overload 只取第一个**：`TargetProfile.findMethodSpec` 返回首个匹配（`TargetProfile.java:60-75`）。`LivePromotion#listFromJson`、`MMKV#decodeString` 各有两条 spec，若走 Profile 方法解析会命中错误 overload；目前这些 hook 都绕过了 Profile，所以未触发。
5. **缓存 key 过粗**：`MountResolver` 的 `CLASS_CACHE/METHOD_CACHE` 只用 `spec.id`，不含 class/ClassLoader（`MountResolver.java:22-23,32-35,81-84`）。当前单进程单 Loader 下安全；热重载/多 Loader 场景可能复用错误结果。
6. **check-mounts 的版本断言可被静默跳过**：找不到 `aapt2` 时只 WARN（`tools/check-mounts.sh:144-161`），与“必须断言 versionCode”不一致。建议 aapt2 缺失时直接 ERROR（或显式 `--allow-version`）。
7. **`method_kind IS NOT NULL` 的语义被文档夸大**：它排除的是方法引用（NULL），并不排除 abstract/interface 声明（dexsql 只有 virtual/direct/NULL 三种）。`2.0.0-ARCH.md:184` 的“排除纯接口/抽象声明”不准确。实测 133 条命中中没有 abstract 方法，当前无实际影响。
8. **check-mounts 的 CRLF/可移植性**：`tools/check-mounts.sh` 工作区版本有 416 行 CRLF；Git Bash 下可运行，但 Linux/macOS 上直接运行可能出问题。`.gitattributes` 会在提交时归一为 LF，仍建议本地先转 LF 再验证。另外脚本使用 `declare -A`，macOS 自带 bash 3.2 不支持。
9. **`grep -qi 'error' "$ERR"` 可能误报**：`tools/check-mounts.sh:320-324`，若 dexsql stderr 含 “0 errors” 之类文本会直接 ERROR。
10. **`:play` 进程会覆盖主进程状态**：`Hooks.installPlayOnly` 调用 `HookState.flush()`（`Hooks.java:60-73`、`HookState.java:193-195`），而 `HookState.init` 在所有进程都执行（`CloudMusicToolModule.java:38-43`）；`:play` 只有 AUDIO_CLIP_AD，可能把模块 App 的 `state` 覆盖成单功能快照。1.2.0 已存在，非 2.0.0 引入，但与“避免空快照覆盖主进程数据”的注释不一致。
11. **VersionGate 先按 versionCode 拒绝**：`VersionGate.java:96-116` 对 versionCode 非 9006008 的包直接跳过（即使 versionName 是 9.6.08），相比 1.2.0 只看 versionName 更严格；渠道包/重签包可能被误拦。若这是有意行为，建议在 CHANGELOG 写明。
12. **ProfileExportTest 只校验 Profile 自身**：`ProfileExportTest.java:120-136` 没有断言“每个 hook 安装点都在 Profile 中”，因此 P1-4 的漏项无法被测试发现。建议补一个 hook→Profile 的静态/单测校验，或让 hook 只通过 Profile 取坐标。
13. **版本号硬编码三处**：`ProfileRegistry.java:13`、`VersionGate.java:17`、`tools/check-mounts.sh:151` 都写死 9006008，新增版本容易漂移。
14. **lint 25 Warning**：`PrivateApi`（反射 `ActivityThread`）、`ExportedContentProvider`（StatusProvider/XposedProvider）、`StaticFieldLeak` 等；无 Error，不阻断，但建议在发布说明中确认 StatusProvider 的 UID 校验仍是唯一入口。
