## P0

### P0-1 黑名单未覆盖“免广告/免费收银台”具体 key，可被 UI 提升后强开

`app/src/main/java/com/cloudmusictool/app/AbTestPolicy.java:53-58` 的正则只包含 `adfree`、`freeflow`，不匹配带下划线/连字符的实际 key：

- `ad_disable_ad_free_play_task`、`ad_disable_ad_free_play_task_retry_opt_android`（`docs/phase2/abtest-research.md:916,1180` 明确标注“广告/付费边界，禁止”）
- `hy-freetscashierbox-list-android`（`abtest-research.md:1179` 免费/付费收银台）

这些 key 不在 `CURATED_KEYS`（`AbTestPolicy.java:18-41`），但会出现在“已探测实验”列表；用户点击“提升为强开”后，`ExperimentFragment.applyForce`（`ExperimentFragment.java:282-310`）用 `isAllowed` 校验会通过，写入 `abtest_force_map` 后 `Config.parseForceMap`（`Config.java:128-171`）和 `AbTestHooks.forcedGroup`（`AbTestHooks.java:210-225`）也会放行。契约把“免广告”列为黑名单必须覆盖项（`1.2.0-CONTRACT.md:9-12` 与 §8.3），因此这是硬边界缺口。直接改 DB 同样绕过（两层过滤共用同一正则）。

修复建议：正则加入 `ad[_-]?free|free|reward` 等（确认不误伤 curated），或把 §8.3 的禁止 key 做成显式集合与正则取并集；补 `AbTestPolicyTest` 用例。

## P1

### P1-1 `:play` 进程用空快照覆盖主进程的观测数据

`CloudMusicToolModule.java:82-88` 对 `:play` 走 `Hooks.installPlayOnly` 后仍无条件执行 `ExperimentState.flush()`。`:play` 进程 `ExperimentState.init` 已在 `onModuleLoaded` 执行（`CloudMusicToolModule.java:38-41`），但该进程不安装 AbTest hook（`Hooks.java:59-68`），`sItems` 为空；`buildJson`（`ExperimentState.java:132-168`）会生成 `{"updatedAt":...,"items":[]}`，`doPublish`（`ExperimentState.java:170-200`）以 `type=experiments` 写入 `StatusProvider`（`StatusProvider.java:68-71`），覆盖主进程刚写入的数据。主进程若暂无新命中，实验页会一直显示“暂无观测数据”，直接破坏验收项“冷启动后实验页能看到实际命中的 key”。

修复：只在主进程调用 `ExperimentState.flush()`（例如 `if (!playProcess)`），或让 `ExperimentState` 在 `:play` 不初始化/不发布。顺带注意 `HookState.flush()` 在 `installPlayOnly` 也有同类问题（`Hooks.java:67`，1.1.0 既有行为），建议一并确认。

### P1-2 黑名单其余缺口（§8.3 明确禁止但正则未覆盖）

同一正则（`AbTestPolicy.java:53-58`）未覆盖：

- `FH-kv-*` / `kv-*`（`abtest-research.md:1181`，KV/Cookie 存储，可能影响登录态/风控）
- `guardian` 语义（`abtest-research.md:1188`）
- `Xcrash` / `XCrash2` / `XCrash4`（`:1210`，崩溃采集）
- `shieldEnable`（`:1213`，安全防护）
- `androidhttps` / `aosApiHttps` / `aosCDNHttps`（`:1214`，HTTPS 策略）
- `androidnapm` / `androidbi` / `ab-tombstone-collect-data`（`:1215-1216`，监控/采集）
- `wait-task-0805-v2` / `cold-start-26H2-aos` / `startup_task_play_process`（`:1225`，启动顺序/稳定性）
- `rewarded-video-ads`（`:1227`，广告收入/付费权益）

这些 key 被提升后都会被放行。虽然需要用户显式操作，但契约要求“任何涉及账号、权益、内容权限、支付、广告收入的 key 默认拒绝”（`abtest-research.md:1111`），建议全部补入黑名单并加测试。

### P1-3 remote prefs 写入失败/未绑定无提示，UI 仍显示“已保存”

`ConfigStore.putString`（`ConfigStore.java:60-74`）在 `mRemote == null` 时静默写模块本地 prefs，仅打日志；`ExperimentFragment.writeForceMap`（`ExperimentFragment.java:334-343`）无返回值，`applyForce`（`:307-309`）无条件 toast“已保存”。此时目标进程读不到配置，用户却以为已生效。现有 `SettingsFragment` 已用 `mStore.remote()` 在未绑定时禁用开关（`SettingsFragment.java:78,139`），实验页没有采用。

修复：`putString` 返回 boolean；`applyForce`/`confirmReset` 失败时提示“写入失败/框架未绑定”；或在 `rebuild` 时按 `mStore.remote()` 禁用所有可写项。

### P1-4 版本号未升到 1.2.0

`app/build.gradle:19-20` 仍是 `versionCode 3` / `versionName "1.1.0"`；实跑 `assembleRelease` 产物为 `app/build/outputs/apk/release/cloudmusictool-1.1.0.apk`，`CHANGELOG.md` 无 1.2.0 条目。若按 1.2.0 发布，这是发布阻塞项。

## P2

1. **`Config.parseForceMap` 无单测**：`ConfigTest.java` 只测 `loadSet`，未覆盖非法 JSON、非法 group、黑名单 key、空 Map、`null` 值回退（`Config.java:128-171`）。`AbTestPolicyTest.java:20-83` 覆盖了 curated/黑名单/boot-/promoted/非法 group/精确匹配，但未覆盖 P0-1 的具体 key、`guardian`、`Boot-` 大小写。
2. **`boot-` 前缀大小写敏感**：`AbTestPolicy.java:71` 只匹配小写 `boot-`；`Boot-*` 可被提升。建议 `key.toLowerCase(Locale.ROOT).startsWith("boot-")`。
3. **`sObservedKeys` 无上限**：`AbTestHooks.java:45,392` 对每个新 key 永久入 Set，即使 `ExperimentState` 已达 500 key 上限；服务端若下发大量 key 会持续占内存。建议加容量上限或复用 `ExperimentState` 的容量判断。
4. **`sItems.size()` 竞态**：`ExperimentState.java:90-96` 先查 `size()` 再 `putIfAbsent`，并发下可略超 `MAX_TRACKED_KEYS`；影响很小，可改为先插入后判断/清理。
5. **强开命中被计数两次**：`b#x` 返回合成 config 后（`AbTestHooks.java:145-166`），`ABTestManagerImpl#checkExperiment` 的 after hook 又 observe 一次（`:90-106`），同一调用在 UI 里 count +2，source 也会从 `model` 变成 `libra/old`。建议在 manager hook 识别“已由 model hook 记录”或只在 manager 层计数。
6. **source 取值与契约不一致**：`b#x` 记录 `"model"`（`AbTestHooks.java:155,161`），契约示例只列 `libra|old|startup`（`1.2.0-CONTRACT.md:26-30`）。需在文档中补 `model` 或统一取值。
7. **合成 `LibraABTestConfig` 未初始化 `log/expInfo/timestamp`**：`AbTestHooks.java:265-287` 只写 4 个字段（符合契约“只改 4 字段”），但 `LibraABTestConfig` 的 `expInfo` 为 null；若业务读取 `expInfo` 可能 NPE。需真机验证，或合成基类 `ABTestConfig`（契约允许失败回退基类，也可考虑优先基类）。
8. **`clientConfig` 空 Map 的影响未文档化**：`AbTestHooks.java:282` 给空 `HashMap`，会使 `checkExperimentWithParam` 全走默认值、`checkClientConfig` 返回空 Map 而非 null。契约要求“可接受但要在文档说明”，但 `1.2.0-CONTRACT.md` 未写这一点。
9. **`ExperimentFragment` 绕过 `StatusProvider.readExperiments`**：`ExperimentFragment.java:33-35,347-352` 直接按固定 `hook_status`/`experiments` 读取，`StatusProvider.readExperiments`（`StatusProvider.java:121-128`）成为死代码；prefs 文件名/key 变更时会静默失配。建议改用静态方法。
10. **`applyForce` 的 `promote` 参数未使用**：`ExperimentFragment.java:282` 声明但方法体从未引用；`readForceMap`（`:312-332`）只过滤非法 group，不过滤黑名单，已强开列表可能展示禁止 key（不影响运行时，但文案/计数不一致）。
11. **热路径开销可接受但可优化**：`ExperimentState.record` 在每次 `checkExperiment`/`b.x` 执行 `ConcurrentHashMap.get` + `synchronized` + `System.currentTimeMillis` + CAS（`ExperimentState.java:83-102`）；`groupOf` 对空 group 每次回退 `findField`（`AbTestHooks.java:339-348`）。无全局锁竞争，日志已限流（`AbTestHooks.java:395-401,404-418`），启动期可接受。
12. **`buildJson` 截断循环最坏 O(n²)**：`ExperimentState.java:159-163` 每次删一项后重新 `toString()`，n≤200 且在工作线程，可接受；可改为先估算/批量删。
13. **`resolveConfigClasses` 失败后不再重试**：`AbTestHooks.java:227-259` 一旦失败也置 `sConfigResolved=true`，类加载时序异常时强开永久失效且只有一条 warn。
14. **`StatusProvider` 未知 `type` 落到 `state`**：`StatusProvider.java:68-69` 只有 `experiments` 特判，其他任意值都写 `state`。建议白名单化 `mounts|experiments`，避免未来新增类型误写；不影响当前 UID 校验。
15. **4 Tab 状态恢复**：`MainActivity.java:39-51` 依赖 `FragmentManager` 自动恢复；`savedInstanceState != null` 时不调用 `showTab`，若 fragment 未恢复会得到空容器（标准行为，可加兜底）。
16. **图标深色主题**：`res/drawable/ic_experiment.xml` 硬编码 `#FF000000` stroke，依赖 `BottomNavigationView` 的 tint；若 tint 未覆盖 stroke 会偏黑，建议统一用 `?attr/colorControlNormal` 或 tint。
17. **`tools/check-mounts.sh` 未纳入 ABTest 挂载点**：本次 5 个挂载点只能靠人工 dexsql 复核，建议加进脚本防版本漂移。

## 性能

- 观测在 `checkExperiment`/`b.x` 热路径：`record` 为 `ConcurrentHashMap.get` + 每项 `synchronized` + `AtomicInteger` + `currentTimeMillis` + CAS；无全局锁，日志已限流，500 key 上限。启动期可接受，但属于新增常驻开销（P2-11）。

- `ExperimentState` 与 `HookState` 各有一个单线程 daemon executor，互不阻塞。
