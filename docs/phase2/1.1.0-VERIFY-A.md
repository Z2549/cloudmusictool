## 2. UI-02 真机探针（真机实测，2026-10-20 19:33）

进程 `com.netease.cloudmusic` PID 26973，日志 tag `LSPosedFramework`（模块 `module.log` 输出到该 tag），探针标签 `PROBE`。

### 2.1 渲染路径结论

```
ArkFragmentV3.Hc
  -> BaseArkV3Fragment.Tc(list)          // 6 个 DiscoveryTabInfoV3
  -> BaseArkV3Fragment.Lc(list)          // 6 个
  -> dr.h.T0(list)                       // 写入适配器 ArrayList b
       -> RecyclerView.Adapter.notifyDataSetChanged()
            -> theme.ui.tab.r$a.onChanged()
                 -> MusicTabLayout.addTab(k, position, false)
                 -> MusicTabLayout.addTab(k, false)
  -> BaseArkV3Fragment.hc(list, ViewPager2, TabLayout)  // 默认选中
  -> BaseArkV3Fragment.ad()              // 按 getTabCount() 逐项 Uc/Ac 配置
```

关键证据：

- `PROBE BaseArkV3Fragment#Tc/1`：入参 6 个 `DiscoveryTabInfoV3`。
- `PROBE dr.h#T0/1`：入参同为 6 个；`getItemCount` 在 T0 后返回 6。
- `PROBE MusicTabLayout#addTab/3` 的调用栈：
  `MusicTabLayout.addTab <- theme.ui.tab.r.d <- r$a.onChanged <- RecyclerView.Adapter.notifyDataSetChanged <- dr.h.T0 <- ArkFragmentV3WithQuickListen.Hd <- Hc`
- `PROBE BaseArkV3Fragment#Uc/2` 在 T0 之后按 index 0..5 调用；`Uc` 内部只设置标题/图标并调用 `Ac`，**不直接 addTab**。
- `PROBE dr.h#createFragment/1` 使用 `dr.h.b`（即 T0 写入的列表）按 position 取数据。

### 2.2 对实现的指导

- 真正删除点是 `dr.h.T0(List)` 的入参：替换为过滤后的新 `ArrayList` 后，
  `getItemCount()` 自然返回保留数，`createFragment(position)` 的索引天然是保留索引，
  不需要额外的「保留索引 → 原始索引」映射表（映射由列表本身承担）。
- `hc(List, ...)` 同时过滤，保证默认选中项落在保留列表内。
- `Tc/Lc/getTabDataList` 一并过滤，避免其它调用方拿到未过滤数据。
- `MusicTabLayout.addTab` 作为兜底：只在数据层确实过滤过时启用；先移除 `k.r`（预创建 TabView）
  再 `removeTab`，且任何情况下不移除最后一个 tab。
